# User Flows

## Flow: Login
1. User navigates to `/login`
2. Enters email and password
3. Submits form → `POST /api/auth/login`
4. Backend validates credentials, returns `{ token, user }`
5. Frontend stores in localStorage, redirects to `/`
6. Protected routes check JWT validity

## Flow: Raise a Ticket
1. User navigates to `/raise-ticket`
2. Fills title and description
3. Optionally searches and links an inventory asset
4. Submits → `POST /api/tickets`
5. Backend creates ticket (status: Open, team: IT Help Desk)
6. Returns created ticket ID
7. User sees confirmation and is redirected to `/tickets`

## Flow: Resolve a Ticket
1. Team member logs in, navigates to `/tickets`
2. Filters by their team or status
3. Clicks ticket → views details and work notes
4. Updates status to "In Progress" → `PATCH /api/tickets/:id/status`
5. Adds work notes via `POST /api/tickets/:id/notes`
6. Updates status to "Resolved" or "Closed"
7. History logged immutably in ticket_history

## Flow: Add an Asset
1. Admin/Help Desk navigates to `/inventory`
2. Clicks "Add Asset"
3. Fills all required fields (category, description, user, status)
4. Provides serial_number OR mac_address
5. Asset ID auto-generated by backend
6. Duplicate check rejects if serial/MAC already exists
7. Saves → asset appears in inventory list

## Flow: Manage Users
1. Admin navigates to `/users`
2. Clicks "Add User" or "Edit" existing user
3. Fills name, email, phone, role, password
4. Save creates/updates user
5. Toggle activate/deactivate disables login
6. Reset password updates hash only
